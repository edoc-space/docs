# Темы оформления

Тема меняет оболочку, компоненты и стили сайта. Документы, адреса, языки и поиск остаются данными движка. Без настройки используется стандартная тема `default`, поставляемая с E-Doc.

## Выбор темы

Настройка находится только в **корневом** `local/storage/edoc/site.json`:

```json
{
  "theme": { "id": "local" }
}
```

Значения `id`:

| Значение | Источник |
| --- | --- |
| `default` или отсутствие `theme` | Стандартная тема движка. |
| `local` | Каталог `theme/` в контентном корне сайта. |
| `@vendor/theme-name` или `theme-name` | Уже установленный npm-пакет с `theme.json`. |

Локализованный `ru/site.json`, front matter, query string и HTTP-заголовки не выбирают тему и не задают путь импорта. Локали используют одну сборку сайта.

Для локальной темы достаточно такого дерева:

```text
local/storage/edoc/
├── site.json
└── theme/
    ├── theme.json
    ├── index.tsx
    └── theme.css
```

`theme/theme.json`:

```json
{
  "contractVersion": 1,
  "entry": "index.tsx"
}
```

`entry` — существующий JS/TS-модуль внутри темы. NUL, управляющие символы и URL/query-синтаксис отвергаются до обращения к файловой системе. Выход через `..`, абсолютные пути и внутренние символические ссылки запрещены. Сам контентный корень или корень установленного пакета может подключаться символической ссылкой.

## Контракт v1 и fallback

`theme/index.tsx` экспортирует объект `SiteTheme`. CSS тема импортирует из своего entry:

```tsx
import React from 'react';
import { defaultSlots } from '@/Themes/api';
import type { SiteTheme, SiteHeaderProps } from '@/Themes/api';
import './theme.css';

function Header(props: SiteHeaderProps) {
  const DefaultHeader = defaultSlots.Header;
  return <DefaultHeader {...props} className={`${props.className} custom-header`} />;
}

export default {
  contractVersion: 1,
  slots: { Header },
} satisfies SiteTheme;
```

Каждый пропущенный slot использует стандартный компонент. Через `defaultSlots` тему можно строить композиционно, сохраняя поисковую строку, выбор языка и mobile-меню. При полной замене шапки передавайте `afterNav`, `mobileControls` и локали: документация использует эти точки для поиска, версий и мобильного оглавления.

| Slot | Тип props | Ответственность |
| --- | --- | --- |
| `SiteShell` | `SiteShellProps` | Корневой контейнер с `kind`, `children`, HTML-атрибутами. |
| `Header` | `SiteHeaderProps` | Навигация, бренд, локали, активный адрес, дополнительные элементы. |
| `Footer` | `SiteFooterProps` | Подвал из конфигурации и навигации. |
| `Page` | `PageProps` | Полное представление обычной страницы. |
| `Documentation` | `DocumentationProps` | Полное представление документации, дерева, поиска и TOC. |
| `Error` | `ErrorProps` | Ошибки с HTTP-статусом, заголовком, текстом и ссылками. |

Полные типы экспортируются из `@/Themes/api`. Там же доступны `defaultSlots`, `MarkdownDocument`, `MdxDocument`, `mergeLocaleAlternates` и `usePageScrollRestoration`. Остальные внутренние компоненты не являются контрактом темы.

`Page`, `Documentation` и `Error` заменяют целое представление. Если вы пишете их самостоятельно, вызывайте нужные оболочку, шапку и подвал своей темы. Стандартные представления делают это автоматически. Данные в props остаются исходными: тема не должна менять slug, обходить диагностику или загружать другие модули по входу посетителя.

Точки блога будут добавлены вместе с модулем блога; эта версия не добавляет blog routes или публикации.

## Слои CSS

Порядок: foundations ReactSoftBox → общие content/layout styles → tokens стандартной темы → CSS выбранной темы. В `theme.css` можно переопределить CSS variables, например `--color-body-bg`, `--color-text`, `--color-muted`, `--color-line`, `--font-sans`, `--font-mono`, `--surface-card`. Используйте `:root, :root[data-theme="light"]`, если заменяете стандартные tokens.

Полная тема может менять компоновку и разметку через slots. Проверьте контраст, `:focus-visible`, клавиатуру, закрытие меню по Escape, mobile, длинные заголовки, код, картинки, языки, поиск, TOC и MDX. Дополнительный dark mode эта версия не обещает.

## Установленные пакеты

Один пакет представляет одну тему и содержит обычный `package.json`, `theme.json` и entry. Resolver ищет пакет по имени в `node_modules` контентного корня, затем `local/plugins/node_modules` и `node_modules` движка. Приоритет нужен для воспроизводимого выбора; один и тот же пакет не следует устанавливать в нескольких местах с разными версиями.

Устанавливайте зависимости заранее в закреплённом build-профиле и фиксируйте их версии. HTTP и PHP runtime не скачивают пакеты и Git. Наличие пакета требуется и при сборке, и на PHP-сервере для проверки fingerprint. Новый встроенный установщик тем не добавляется.

Стандартная тема остаётся в движке. Дополнительные официальные темы планируются пакетами одного общего репозитория; сторонние темы хранятся у авторов. Отдельный Git-репозиторий для каждой темы не требуется. Приватный дизайн храните только в своём контентном репозитории; не переносите его в публичные примеры.

## Production-сборка и диагностика

Из каталога движка выполните `yarn build` в настроенной среде конкретного сайта. Сборка использует `local/storage/edoc/site.json`; если контент подключается извне, его root должен быть смонтирован здесь и при сборке, и в PHP. Для сайтов этого workspace применяется отдельный профиль backend/me, с отдельными outputs.

Vite создаёт `public/build/theme.json` schema 2: `schemaVersion`, `id`, `source`, `contractVersion`, `fingerprint` и `inputs`. В `inputs` записаны хеши реально потреблённых файлов и неглубоких списков каталогов с относительными ссылками на логические корни; абсолютных путей нет. Manifest schema 1 считается устаревшим и требует новой сборки.

Fingerprint включает исходники движка/темы, реальные transitive JS/npm imports, импортированные assets (в том числе `resources/images/logo.svg`), CSS `@import` и `url()`, package.json зависимостей и файлы подготовки сборки. Списки каталогов замечают добавление кандидатов разрешения импорта, включая пакеты в существующем scope (`@vendor`) каждого вложенного или подключённого ссылкой `node_modules`. Появление служебных `local/cache`, `local/logs`, `local/tests` движка и build-cache не меняет эти списки; если файл оттуда явно импортирован, его содержимое проверяется как обычный вход. PHP проверяет зафиксированные входы, не обходит весь `node_modules`; `.git` и `node_modules` отсекаются до рекурсивного обхода базового дерева темы.

Поддерживаемые файловые корни: сайт, движок, выбранная тема и установленные зависимости в трёх описанных `node_modules`. Внешний helper или asset внутри корня сайта может лежать вне `theme/`. Пакетная тема может использовать соседние установленные пакеты и API движка. Файловый импорт за пределами этих корней отклоняется при сборке с безопасным `theme.invalid`; перенесите helper/asset в поддерживаемый корень. Плагины сборки должны сообщать дополнительные зависимости через стандартный `addWatchFile`: существующий файл либо каталог, абсолютный путь или путь относительно рабочего каталога процесса сборки, независимо от Vite root. У явно объявленного каталога учитывается всё вложенное дерево, включая скрытые каталоги: содержимое файлов, добавление и удаление элементов. В manifest раздельно сохраняются идентичность объявленного пути (`resolve`), file-хеши и точные `watchdir`-списки; PHP проверяет эти записи без поиска новых поддеревьев. Смена назначения symlink в объявленном файле, каталоге или промежуточной части пути делает старую сборку устаревшей, даже если прежний target остаётся на диске. Разрешение каждой ссылки фиксируется до устранения повторного обхода canonical target. Перед диагностикой сбрасывается PHP realpath cache, чтобы переключение из другого процесса не скрывалось в живущем worker. Исключения служебных каталогов для обычных resolution inventories здесь не применяются. Отсутствующий вход, специальный файл или symlink за разрешённые корни отклоняется с `theme.invalid`, а не пропускается; виртуальный/generated модуль без такого объявления не может обещать проверку скрытых входов. HTTP-адреса и намеренно публичный static, читаемые браузером во время выполнения, не являются импортами сборки и не включаются в fingerprint по содержимому ответа.

После изменения любого зафиксированного входа пересоберите сайт. Вместе с PHP размещайте соответствующие assets и зависимости; одного редактирования `site.json` недостаточно.

В `APP_ENV=prod` PHP проверяет manifest до выдачи приложения. При ошибке возвращается 503 с `Cache-Control: no-store`, понятным кодом и инструкцией, без загрузки неправильного bundle:

| Код | Исправление |
| --- | --- |
| `theme.unknown` | Проверьте `id`, наличие локальной темы или установленного пакета. |
| `theme.incompatible` | Выберите тему с `contractVersion: 1`. |
| `theme.invalid` | Исправьте JSON, entry или недопустимые файловые ссылки. |
| `theme.stale` | Пересоберите этот сайт и обновите manifest/assets вместе с исходниками. |

В dev/test production guard отключён, чтобы адресные тесты и подготовка не требовали готового bundle. Ошибки resolver при самой сборке проверяются во всех окружениях.

## Общие блоки и состояния

Тема оформляет семантические области общей карточки (`markdown-card__media`, `markdown-card__metadata`, `markdown-card__content`, `markdown-card__actions`) и панель `collection-filters`. Данные, канонические ссылки, public summaries и серверный отбор не переносятся в тему. Можно заменить Blog slots, сохранив их props и настоящие URL. UI/head RSS формируются из одной локали.

[Каталог блоков](block-catalog.mdx) показывает один набор в выбранной теме: поля и их ошибки, кнопки, метки, вкладки, FAQ, уведомления, диалог, подсказку и медиа. Диалог использует общий lifecycle фокуса, вкладки поддерживают стрелки/Home/End; экземпляры независимы. Внешнее видео загружается только по действию. Формы не выполняют отправку. Новые анимации учитывают reduced motion.

Для локальной темы сохраняйте собственные CSS/assets в её репозитории, а публичные примеры и снимки руководства — в default. Полноширинный декоративный слой ограничивайте так, чтобы он не увеличивал горизонтальную область документа.

### Геометрия документации и общих блоков

Оболочка docs измеряет фактическую высоту Header через ResizeObserver и передаёт `--docs-header-height` сетке и sticky-панелям. Тема может менять высоту шапки без отдельного фиксированного отступа сайдбара. Подвал расположен рядом с нижней зоной панели. Её высота синхронизируется с фактическим подвалом через `--docs-footer-height`; минимальный размер подвала — `--docs-bottom-height`.

Для media карточки меняйте `--markdown-card-padding`, а не добавляйте рамку вокруг изображения. Вариант ссылки целиком получает фокус на `.markdown-card-link`. MDX Tabs сохраняет штатный UI-kit и клавиатуру; `.markdown-tabs--ui` убирает конфликт legacy clipping/gap, соединяя вкладки и прямоугольную панель. Gallery, Slider и Video занимают не более 860 px и центрируются внутри доступной колонки. На узком экране они заполняют её ширину; подписи, предпросмотр и кнопки переключения сохраняются. Video загружает внешний iframe только по нажатию.
