# Markdown и MDX

В E-Doc можно писать обычные `.md` файлы и `.mdx` файлы с React-компонентами. Начинать почти всегда лучше с Markdown: он проще, читается прямо в репозитории и не требует думать о frontend-коде.

MDX нужен там, где обычного текста уже мало: главная страница, интерактивный блок, OpenAPI, changelog, дерево каталогов или проектный React-компонент.

## Простое правило

- используйте `.md`, если страница состоит из текста, списков, таблиц, ссылок, изображений и блоков кода;
- используйте `.mdx`, если на странице нужен React-компонент;
- не переводите документ в MDX только “на всякий случай”.

Оба файла живут в одной структуре и открываются одинаково:

<DirectoryTree
  title="Markdown и MDX рядом"
  tree={[
    {
      name: 'local/storage/edoc/ru/docs',
      type: 'directory',
      children: [
        { name: 'installation.md', type: 'file', description: 'обычная инструкция' },
        { name: 'quick-start.mdx', type: 'file', description: 'инструкция с DirectoryTree' },
        { name: 'api.mdx', type: 'file', description: 'страница с OpenAPI-компонентом' },
      ],
    },
  ]}
/>

## Что умеет Markdown

Markdown подходит для большинства страниц документации:

```markdown
---
title: Установка
description: Как подготовить окружение.
sidebar_position: 10
---

# Установка

Перед началом проверьте:

- PHP установлен;
- зависимости установлены;
- сайт открывается локально.

[Перейти к настройке](configuration.md)
```

Такой документ легко читать без запуска сайта. Это важно для pull request, review и поиска по репозиторию.

## Таблицы

Markdown-таблицы поддерживаются через GitHub Flavored Markdown:

```markdown
| Возможность | Markdown | MDX |
| --- | --- | --- |
| Обычный текст | Да | Да |
| React-компоненты | Нет | Да |
| Лучше для документации | Да | Когда нужны компоненты |
```

**Как отобразится:**

| Возможность | Markdown | MDX |
| --- | --- | --- |
| Обычный текст | Да | Да |
| React-компоненты | Нет | Да |
| Лучше для документации | Да | Когда нужны компоненты |

Таблицы удобны для коротких сравнений, списков параметров и небольших справочников. Если таблица становится слишком широкой или интерактивной, лучше вынести данные в компонент или отдельный файл.

## Изображения и видео

> Доступно с E-Doc v1.1.0: полноэкранный preview изображений, группировка в галереи и безопасные video-блоки.

Обычное изображение вставляется стандартным Markdown-синтаксисом. При клике E-Doc откроет его в полноэкранном preview, а текст из `title` покажет подписью под изображением:

```markdown
![Горизонтальный пример](/examples/media/cat_hor.jpg "Горизонтальное изображение")
```

**Как отобразится:**

<img src="/storage/edoc/static/examples/media/cat_hor.jpg" alt="Горизонтальный пример" title="Горизонтальное изображение" />

Если изображения должны листаться вместе, объедините их через `gallery` с одинаковым идентификатором. Блоки можно располагать в разных местах страницы:

````markdown
:::gallery install
![Шаг 1](/examples/media/dog_hor.jpg "Первый шаг")
:::

Текст между изображениями.

:::gallery install
![Шаг 2](/examples/media/jack-russell_ver.jpg "Вертикальный кадр")
![Шаг 3](/examples/media/animals_ver.jpg "Еще один вертикальный кадр")
:::

:::gallery after_install
![Результат](/examples/media/jack-russell_hor.jpg "После установки")
:::
````

**Как отобразится:**

<Gallery id="install">
  <img src="/storage/edoc/static/examples/media/dog_hor.jpg" alt="Шаг 1" title="Первый шаг" />
</Gallery>

Текст между изображениями.

<Gallery id="install">
  <img src="/storage/edoc/static/examples/media/jack-russell_ver.jpg" alt="Шаг 2" title="Вертикальный кадр" />
  <img src="/storage/edoc/static/examples/media/animals_ver.jpg" alt="Шаг 3" title="Еще один вертикальный кадр" />
</Gallery>

<Gallery id="after_install">
  <img src="/storage/edoc/static/examples/media/jack-russell_hor.jpg" alt="Результат" title="После установки" />
</Gallery>

Для видео используйте безопасные `video`-блоки. E-Doc не загружает iframe сразу: сначала показывает кнопку загрузки, чтобы сторонние скрипты видеохостинга не выполнялись при простом открытии страницы. Поддерживаются YouTube, RuTube и VK Video:

````markdown
:::video youtube
https://www.youtube.com/watch?v=K4TOrB7at0Y
title="YouTube-пример"
:::

:::video rutube
https://rutube.ru/video/f39214593c1933a60c57de704a5ee8cb/
title="RuTube-пример"
:::

:::video vkvideo
https://vkvideo.ru/video_ext.php?oid=-239594766&id=456239018&hd=3
title="VK Video-пример"
:::
````

Для VK Video берите значение `src` из iframe, который VK показывает в "Поделиться" / "Вставить". Обычная ссылка страницы вида `https://vkvideo.ru/video-239594766_456239018` не является embed-ссылкой и откроется как внешняя ссылка.

**Как отобразится:**

<Video provider="youtube" src="https://www.youtube.com/watch?v=K4TOrB7at0Y" title="YouTube-пример" />
<Video provider="rutube" src="https://rutube.ru/video/f39214593c1933a60c57de704a5ee8cb/" title="RuTube-пример" />
<Video provider="vkvideo" src="https://vkvideo.ru/video_ext.php?oid=-239594766&id=456239018&hd=3" title="VK Video-пример" />

## Code blocks

Для блока кода укажите язык после открывающих backticks:

````markdown
```bash title="terminal"
phpsoftbox up
phpsoftbox vite-dev
```
````

**Как отобразится:**

<pre data-language="bash" data-title="terminal"><code>{`phpsoftbox up
phpsoftbox vite-dev`}</code></pre>

E-Doc покажет такой блок как окно с названием языка, номерами строк и кнопкой копирования.

Если нужен заголовок файла, добавьте `title`:

````markdown
```json title="site.json"
{
  "title": "E-Doc"
}
```
````

**Как отобразится:**

<pre data-language="json" data-title="site.json"><code>{`{
  "title": "E-Doc"
}`}</code></pre>

## Admonitions

Для заметок и предупреждений используйте блоки `note`, `tip`, `info`, `warning` и `danger`:

````markdown
:::note
Обычная заметка рядом с текстом.
:::

:::tip
Совет, который помогает пройти сценарий быстрее.
:::

:::info
Дополнительная информация без критичности.
:::

:::warning
Перед обновлением проверьте, что пользовательский контент лежит в `local/storage/edoc`.
:::

:::danger
Не храните пользовательские файлы внутри core-кода E-Doc.
:::
````

**Как отобразится во всех вариантах:**

## Tabs

Если нужно показать несколько вариантов команды, можно использовать tabs-синтаксис:

````markdown
:::tabs
@tab Yarn
```bash
yarn add @edoc-space/plugin-openapi
```

@tab Npm
```bash
npm install @edoc-space/plugin-openapi
```
:::
````

**Как отобразится:**

<div className="markdown-tabs">
  <div className="markdown-tabs__nav" role="tablist">
    <button type="button" className="markdown-tabs__tab markdown-tabs__tab--active" role="tab" data-tab="yarn" aria-selected="true">Yarn</button>
    <button type="button" className="markdown-tabs__tab" role="tab" data-tab="npm" aria-selected="false">Npm</button>
  </div>
  <div className="markdown-tabs__panels">
    <div className="markdown-tabs__panel markdown-tabs__panel--active" role="tabpanel" data-tab="yarn">
      <pre data-language="bash"><code>{`yarn add @edoc-space/plugin-openapi`}</code></pre>
    </div>
    <div className="markdown-tabs__panel" role="tabpanel" data-tab="npm">
      <pre data-language="bash"><code>{`npm install @edoc-space/plugin-openapi`}</code></pre>
    </div>
  </div>
</div>

Tabs удобны для альтернатив вроде `yarn` / `npm`, Docker / Workspace или Linux / macOS.

## Когда нужен MDX

MDX стоит брать, когда страница должна содержать компонент:

```mdx
---
title: API
slug: api
---

import { OpenApi } from '@edoc-space/plugin-openapi'

# API

<OpenApi source="/storage/edoc/static/openapi.json" />
```

**Как отобразится:**

<OpenApi source="/storage/edoc/static/examples/openapi.json" />

В этом примере Markdown отвечает за текст и заголовки, а `OpenApi` выводит сложный интерфейс из JSON-файла.

## Core-компоненты

Часть компонентов уже входит в E-Doc и не требует установки npm-пакетов:

- `Hero` - первый экран страницы;
- `Section` - смысловой блок страницы;
- `Grid` и `Columns` - сетки;
- `Feature` и `Card` - небольшие карточки;
- `Slider`, `Tabs`, `Testimonial` - визуальные блоки для страниц сайта.

Для таких компонентов используйте import из `@/Components/Mdx`. Если рядом нужен внешний компонент, импортируйте его из npm-пакета:

```mdx
import { Section } from '@/Components/Mdx'
import { DirectoryTree } from '@edoc-space/plugin-directory-tree'

<Section title="Структура">
  Контент проекта лежит отдельно от движка.

        { name: 'docs', type: 'directory' },

        { name: 'static', type: 'directory' },

```

## Чего не стоит делать в MDX

MDX может выполнять frontend-код, поэтому его лучше использовать аккуратно:

- не переносите весь текстовый документ в MDX без причины;
- не вставляйте большие данные прямо в JSX-пропсы, если их можно хранить в `static`;
- не импортируйте пользовательские плагины из core `package.json`;
- не смешивайте в одной странице слишком много разных визуальных блоков.

Хороший MDX-документ все еще читается как документация. Компоненты в нем помогают, а не заменяют текст.

## Как выбрать формат

Если сомневаетесь, начните с `.md`. Когда появится конкретная потребность в компоненте, переименуйте файл в `.mdx` и добавьте import.

URL страницы не изменится:

```text
docs/start/quick-start.md  -> /ru/docs/start/quick-start
docs/start/quick-start.mdx -> /ru/docs/start/quick-start
```

**Как это выглядит для читателя:**

Оба файла открываются как одна и та же страница: [docs/start/quick-start](/ru/docs/start/quick-start).

Это позволяет спокойно начинать с простого Markdown и усложнять страницу только тогда, когда это действительно нужно.

## Следующий шаг

Когда вы поняли разницу между Markdown и MDX, можно переходить к [плагинам](/ru/docs/plugins/overview): они добавляют готовые React-компоненты для OpenAPI, changelog и других сложных блоков.

## Публикации блога

Блог использует отдельную opt-in коллекцию `{locale}/blog/`. Для MDX действуют общий runtime и приватный граф статьи: imports из sidecar или `_shared`, без копии React и без попадания черновиков в public build. Новое тело MDX/зависимость и закрытые вложения требуют production-сборки; только date/draft меняют видимость без неё. Подробный пример и граница намеренно публичного static — в [статье о блоге](blog).

## Собственный React-компонент

Компонент сайта хранится в `components/` рядом с `site.json`. Относительный ESM import работает в pages, docs и статьях блога. Компоненты этой папки намеренно публичные: не храните в них закрытый текст, данные или ключи. Помощники только одной статьи остаются в её sidecar или `blog/_shared/`.

```tsx
// components/ComponentExample.tsx
import React, { useContext, useState } from 'react';
import { MdxLayoutContext } from '@edoc/mdx';
import './component-example.css';

export function ComponentExample({ label = 'Count' }) {
  const [count, setCount] = useState(0);
  const { locale } = useContext(MdxLayoutContext);
  return <button onClick={() => setCount(value => value + 1)}>
    {locale?.code} · {label}: {count}
  </button>;
}
```

В этом документе импорт идёт из `../../../components/ComponentExample.tsx`; для `{locale}/pages/index.mdx` используйте `../../components/ComponentExample.tsx`. `@edoc/mdx` предоставляет общие блоки и контекст одного React runtime. Два экземпляра ниже независимы и получают текущую локаль:

<ComponentExample label="Первый" />
<ComponentExample label="Второй" />

![Локальный React-компонент в стандартной теме: независимые экземпляры и текущая локаль](/storage/edoc/static/examples/composition/local-component-ru.png)


Стили импортируются из компонента и попадают в production output. После изменения TSX/JSX, CSS, assets или установленного пакета пересоберите соответствующий сайт: `yarn build` в подготовленной среде. Fingerprint проверяет использованные исходники и метаданные пакетов; устаревшая сборка закрывается диагностикой `theme.stale`/`blog.stale`. Изменение только даты или draft статьи не требует сборки.

Установленный пакет подключается по имени, как `@edoc-space/plugin-directory-tree` выше. Он заранее установлен из `local/plugins/package.json`, экспортирует совместимый React-компонент, объявляет React в peer dependencies и не включает собственную копию React. Автоматическая установка при HTTP-запросе отсутствует. Стиль из `exports["./style.css"]` подхватывается штатным resolver. Сбой разрешения модуля, отсутствующий экспорт, недопустимый deep import или вход другой статьи останавливает подготовку с указанием причины. Публичные pages/docs по-прежнему не могут импортировать `blog/`, включая транзитивные импорты.


## Ссылки-карточки и геометрия блоков

`linkPlacement="card"` делает всю карточку нативной ссылкой. Внутри допустимы текст, изображение и метаданные; независимые ссылки и кнопки используйте с `linkPlacement="title"` или `"action"`. Подробности — [страницы сайта](site-pages).

MDX-вкладки сохраняют Arrow/Home/End, выбранную вкладку и независимое состояние экземпляров. Навигация примыкает к содержимому без лишнего промежутка; внутренняя панель не скругляется. Видеоблок центрируется в доступной ширине и сохраняет явную кнопку загрузки.
