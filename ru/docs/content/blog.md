# Блог

Блог — отдельная коллекция сайта. Он выключен по умолчанию: обычные pages и документация продолжают работать, включая страницу `/blog`. Для включения добавьте в корневой `site.json`:

```json
{
  "timezone": "UTC",
  "blog": { "enabled": true, "page_size": 10 }
}
```

`page_size` задаёт положительный целый размер страницы. Например, при значении 5 список из 13 публичных статей занимает три страницы: 5, 5 и 3 статьи. При размере 6 набор из 17 статей занимает страницы 6/6/5; `?page=4` возвращает 404, а `?page=0` — 400. Размер списка не влияет на limit блока последних статей. RSS доступен по `/blog/rss.xml`; контракт описан в [статье RSS](rss.md). При включении блога страницы с адресом `/blog` или его дочерними адресами нужно перенести: конфликт блокирует проверку контента.

## Создание статьи

Храните статьи в `{locale}/blog/`: `.md` для текста, `.mdx` для интерактивных компонентов. Каталоги `pages` и `docs` сохраняют своё назначение, версии документации не применяются к блогу.

```markdown
---
title: Первая статья
description: Что нового в проекте и как это использовать.
date: '2026-11-13T12:00:00Z'
draft: false
slug: first-post
tags: [php, edoc]
translation_key: first-post
---

## Начало

Статья с [документацией](/docs/content/markdown-and-mdx).
```

`title`, `description` и `date` обязательны для готовой публикации, в том числе будущей. `draft` — boolean, default `false`; неполный черновик может не иметь этих трёх полей. Ошибки YAML, неверная дата, конфликт slug и небезопасные зависимости блокируют сборку даже у черновика. `tags` — список идентификаторов из букв, цифр, `_` и `-`; повторения удаляются.

Без `slug` адрес получается из пути без расширения и завершающего `/index`: `ru/blog/notes/first.md` → `/blog/notes/first`. Смена даты не меняет URL. Первый сегмент `tags`, `archive`, `rss.xml`, `_modules`, адрес `index`, traversal и скрытые пути запрещены. В одной локали slug уникален. Для EN с prefix `/en` та же статья имеет адрес `/en/blog/first-post`. `translation_key` связывает реальные публичные переводы; скрытый перевод не попадает в head.

Необязательный `image` указывает на существующий намеренно публичный файл `/storage/edoc/static/...` или безопасный HTTP(S) URL без credentials. Доступность локального файла проверяется; внешний сервер отвечает за доступность своего URL. Обложка попадает в metadata по абсолютному URL. Title, description, canonical, язык, OG type/url и дата статьи доступны в начальном HTML без JavaScript; полный текст MDX требует JavaScript.


### Приватное превью карточки

Для фотографии или постера, принадлежащего статье, используйте отдельное `preview`, например для `ru/blog/first-post.mdx`:

```yaml
preview: first-post/cover.jpg
```

Путь задаётся относительно каталога исходной статьи и ограничен её sidecar (`first-post/` или каталогом `index.md(x)`). Допустимы PNG, JPEG, WebP, GIF и AVIF; тип должен совпадать с расширением. Traversal, ссылки на другой sidecar, URL, SVG и symlink запрещены. Production-сборка проверяет оригинал и сохраняет неизменённые байты только в закрытом blog output. На запросе MDX ради карточек не исполняется.

Общие summaries списка и `LatestArticles` получают `preview`: защищённый URL текущей сборки или `null`. Вся карточка — одна нативная ссылка с именем заголовка, без вложенных controls. Фото и постер полностью помещаются в media-шапку (`contain`); без изображения шапка отсутствует. Приоритет: доступное `preview`, затем прежнее публичное `image`, затем карточка без картинки.

GET/HEAD проверяют публикацию, сайт, локаль, поколение, metadata, зависимости и hash output до обработки условных и Range-запросов. Draft/future/disabled отзывают доступ на следующем запросе. При отсутствующей, повреждённой или устаревшей сборке список остаётся читаемым без приватного превью; пересоберите сайт для восстановления. Некорректные metadata остаются ошибкой автора, а сборка с отсутствующим оригиналом завершается диагностикой. Изменение `preview` требует новой сборки. Поле `image` и OG остаются намеренно публичными; RSS сохраняет текстовые metadata без приватной картинки. Не копируйте sidecar в `static` ради карточек.

## Теги, годы и страницы

Читатель выбирает один тег, один год или их сочетание с логикой AND. Год определяется в зоне сайта: например, `2025-12-31T23:30:00Z` относится к архиву 2026 в `Europe/Amsterdam`.

| Адрес | Результат |
| --- | --- |
| `/blog` | Первая страница всех публичных статей |
| `/blog?page=2` | Вторая страница |
| `/blog/tags/php` | Статьи с точным тегом `php` |
| `/blog/tags/php?year=2026&page=2` | Вторая страница пересечения тега и года |
| `/blog/archive/2026?page=2` | Вторая страница годового архива |

На первой странице параметр `page` опускается. Смена тега или года сбрасывает страницу и сохраняет второе условие; «Все теги» и «Все годы» снимают соответствующий отбор. Ссылки пагинации сохраняют условия. Прямой вход, reload, Back и Forward восстанавливают выбор из URL. Теги чувствительны к регистру; Unicode-теги, например `заметки`, кодируются в URL обычным percent encoding.

Список, доступные теги и годы строятся из одного текущего публичного набора нужного сайта и языка. Счётчик тега учитывает выбранный год, счётчик года — выбранный тег; известное условие с нулевым пересечением остаётся доступным. Черновики и будущие статьи не добавляют варианты или счётчики. Порядок всегда `date DESC, slug ASC`, включая равные даты.

Нулевой, отрицательный, дробный, пустой или нечисловой `page`, массив вместо `page`/`year` и некорректный четырёхзначный год дают **400**. Значения задаются десятичными цифрами без ведущих нулей. Год допускается от 1000 до 9999; корректный год вне публичного архива даёт 404. Повторные scalar query-параметры следуют штатному разбору PHP: используется последнее значение; итоговый массив отклоняется с 400. Слишком длинный URL может быть отклонён nginx с 414 до приложения. Неизвестный публичный тег/год и страница за последней дают **404**, в том числе очень большой целый номер. Пустой блог и пустое пересечение существующих условий дают **200** с понятным сообщением.

В начальном HTML каждой страницы есть свой canonical, title/description, язык и Open Graph URL; `page=1` и посторонние query не включаются в canonical. Отбор только по году использует `/blog/archive/<year>`. Сочетание тега и года получает `noindex,follow`. Обложка списка берётся из первой статьи текущей страницы, если задана; закрытые данные в head не попадают. `hreflang` у списка указывает только на существующий публичный отбор и номер страницы другой локали — отсутствующая в EN страница 2 не получает выдуманную ссылку. RSS alternate текущей локали включён в initial head; поиск блога не добавляется.

## Дата, черновики и кеш

Публичность требует включённый блог, корректные данные, `draft: false` и наступившую дату. До даты прямой URL статьи и каждый её закрытый файл дают 404. Список сортируется по date DESC, затем по slug ASC. Пустой блог возвращает 200.

По умолчанию зона — UTC. `timezone` принимает IANA-зону, например `Europe/Amsterdam`. Дата без offset использует зону сайта, дата-only означает её полночь. Несуществующее время при переводе часов отвергается; для повторяющегося времени укажите offset, например `2026-10-25T02:30:00+02:00`. Часы host не задают семантику публикации.

При наступлении даты уже подготовленная статья открывается на первом новом запросе, без cron, перезапуска, сборки или очистки metadata cache. Перенос даты в будущее и `draft: true` закрывают новые выдачи тем же способом. Видимость не хранится до TTL: кеш содержит разобранные метаданные, а policy проверяет актуальные часы. Ответы блога и закрытых файлов имеют `Cache-Control: no-store`; ETag/304 и Range не обходят проверку. Для MP4 после проверки публичности и хешей поддерживается один byte range (206), включая suffix/open-ended; недоступный диапазон даёт 416. HEAD возвращает длину полного файла без тела. Другие типы, несколько диапазонов и If-Range получают полный ответ. Все ответы сохраняют no-store; недоступная статья/сборка закрывает и частичные запросы. Это не удаляет уже скачанные bytes, открытые вкладки или историю браузера.

## Интерактивный MDX и закрытые файлы

MDX — доверенный авторский React-код. Для интерактивности используются общий React runtime и MDXProvider приложения; своя копия React не включается в статью.

```mdx
import { Counter } from './first-post/Counter.jsx'

## Пример

<Counter />
```

```jsx
// ru/blog/first-post/Counter.jsx
import { useState } from 'react';
export function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(value => value + 1)}>{count}</button>;
}
```

Для `first-post.mdx` закрытые helpers, CSS, шрифты и media лежат в sidecar `first-post/`. Для `notes/index.mdx` это каталог `notes/`; чужие статьи и их ресурсы остаются запрещены. Общие приватные helpers можно хранить в `{locale}/blog/_shared/`: они дублируются в каждом приватном графе. Служебные `_shared/*.mdx` не являются дополнительными статьями.

Разрешены обычные imports, literal dynamic import и конечные `import.meta.glob`, если всё замыкание остаётся внутри разрешённых корней. Вычисляемые/сетевые imports, авторский `@vite-ignore`, произвольные runtime deep imports, symlinks, workers/WASM и межстатейные зависимости блокируются. Разрешённые общие exports: `react`, `react/jsx-runtime`, `react-dom`, `react-dom/client`, `@mdx-js/react`, `@edoc/mdx` (авторские блоки и общие MDX contexts). Приватные зависимости не импортируются в тему, pages/docs или публичный app.

Markdown использует ту же защиту вложений:

```markdown
![Иллюстрация](first-post/cover.svg)
[Файл](first-post/notes.pdf)
[Другая статья](second-post.mdx)
[Страница](../pages/about.md)
[Документация](../docs/start/cache.md)
```

Локальные закрытые вложения находятся в sidecar статьи и требуют сборки. `static/` всегда публичен: файл там не становится секретным из-за ссылки из черновика. Не помещайте туда закрытый текст, изображения или исходники. Ссылки не дают чтение произвольных файлов сервера и запрещают опасные схемы.

Относительная ссылка на существующую статью сохраняет её канонический URL, даже если дата ещё не наступила или публикация отозвана. Исходная статья продолжает открываться, а закрытая цель возвращает 404; её заголовок, описание и текст не добавляются в ответ исходной статьи. Fragment вложения сохраняется в Markdown и MDX: например, `first-post/cover.svg#diagram` или `first-post/notes.pdf#page=2`, включая reference-синтаксис. Он не участвует в поиске файла и не обходит проверку публикации. Корректное `%HH`-кодирование fragment не кодируется повторно; закодированные пути файлов остаются запрещены.

## Production-сборка

Запускайте штатную production-команду сайта `yarn build` в его настроенной среде. Она сначала собирает общий app и стабильные ESM facade entries, затем отдельный приватный граф каждой статьи, включая future и drafts. Никаких private chunks в публичном manifest, public/static или sourcemaps нет.

Публичные outputs лежат в `public/build`. Приватные — сохраняемые artifacts в `local/build/blog/<generation>/<article-key>/`, с закрытым `active.json`. Этот каталог не относится к metadata cache и не удаляется cache prune. PHP читает его; nginx не должен иметь alias на него. Сохраняйте его отдельно для каждого сайта вместе с соответствующими public build и исходниками. Во время активации несогласованных частей выдача закрывается; после завершения активируется только законченная generation.

Новое тело MDX, новый/изменённый helper, CSS, media или закрытое вложение требуют новой сборки. Только date/draft меняют видимость без неё. Несовпавшие body/input digests требуют пересборки, старое тело не выдаётся под новыми метаданными. Старые generation, чужой сайт/локаль, несовместимый ABI и повреждённые файлы недоступны. Закрытый namespace `/blog/_modules/...` постоянно проходит guard, даже при выключении блога и наличии одноимённого файла в public.

Темы могут заменить `BlogList` и `BlogArticle` через [общий контракт](themes), сохраняя policy и URL движка. Незаполненные slots используют default. Отборы и страницы используют тот же контракт в обеих темах. RSS доступен по `/blog/rss.xml`; контракт описан в [статье RSS](rss.md).

## RSS и последние статьи

В стандартной теме ссылка RSS в списке и статье открывает ленту `/blog/rss.xml` текущей локали. В ней все актуальные публичные summaries в порядке `date DESC, slug ASC`, без пагинации и отбора по тегу/году. Дата и draft проверяются той же политикой, что в списке и [подборке последних статей](content-model.mdx#последние-статьи-на-странице). Description берётся из метаданных, тело MDX не исполняется. Email-формы, сбора адресов и доставки сообщений нет. Подробности — в [статье RSS](rss.md).
