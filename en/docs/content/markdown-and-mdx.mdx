# Markdown and MDX

In E-Doc, you can write regular `.md` files and `.mdx` files with React components. It is usually better to start with Markdown: it is simple, readable directly in the repository, and does not require thinking about frontend code.

Use MDX when plain text is not enough: a home page, interactive block, OpenAPI reference, changelog, directory tree, or a project-specific React component.

## Simple rule

- use `.md` when the page contains text, lists, tables, links, images, and code blocks;
- use `.mdx` when the page needs a React component;
- do not convert a document to MDX just in case.

Both file types live in the same structure and open the same way:

<DirectoryTree
  title="Markdown and MDX side by side"
  tree={[
    {

## What Markdown can do

Markdown is enough for most documentation pages:

```markdown
---
title: Installation
description: How to prepare the environment.
sidebar_position: 10
---

# Installation

Before starting, check:

- PHP is installed;
- dependencies are installed;
- the site opens locally.

[Go to configuration](configuration.md)
```

This document is easy to read without running the site. That matters for pull requests, review, and repository search.

## Tables

Markdown tables are supported through GitHub Flavored Markdown:

```markdown
| Feature | Markdown | MDX |
| --- | --- | --- |
| Regular text | Yes | Yes |
| React components | No | Yes |
| Best for docs | Yes | When components are needed |
```

**Rendered example:**

| Feature | Markdown | MDX |
| --- | --- | --- |
| Regular text | Yes | Yes |
| React components | No | Yes |
| Best for docs | Yes | When components are needed |

Tables are useful for short comparisons, parameter lists, and compact references. If a table becomes too wide or interactive, move the data into a component or a separate file.

## Images and Video

> Available since E-Doc v1.1.0: fullscreen image preview, gallery grouping, and safe video blocks.

Insert a regular image with standard Markdown syntax. When clicked, E-Doc opens it in a fullscreen preview, and text from `title` is shown as the image caption:

```markdown
![Horizontal example](/examples/media/cat_hor.jpg "Horizontal image")
```

**Rendered example:**

<img src="/storage/edoc/static/examples/media/cat_hor.jpg" alt="Horizontal example" title="Horizontal image" />

When images should be browsed together, group them with the same `gallery` id. Blocks can be placed in different parts of the page:

````markdown
:::gallery install
![Step 1](/examples/media/dog_hor.jpg "First step")
:::

Text between images.

:::gallery install
![Step 2](/examples/media/jack-russell_ver.jpg "Vertical shot")
![Step 3](/examples/media/animals_ver.jpg "Another vertical shot")
:::

:::gallery after_install
![Result](/examples/media/jack-russell_hor.jpg "After install")
:::
````

**Rendered example:**

<Gallery id="install">
  <img src="/storage/edoc/static/examples/media/dog_hor.jpg" alt="Step 1" title="First step" />
</Gallery>

Text between images.

<Gallery id="install">
  <img src="/storage/edoc/static/examples/media/jack-russell_ver.jpg" alt="Step 2" title="Vertical shot" />
  <img src="/storage/edoc/static/examples/media/animals_ver.jpg" alt="Step 3" title="Another vertical shot" />
</Gallery>

<Gallery id="after_install">
  <img src="/storage/edoc/static/examples/media/jack-russell_hor.jpg" alt="Result" title="After install" />

For video, use safe `video` blocks. E-Doc does not load the iframe immediately: it shows a load button first, so third-party video scripts do not run when the page is only opened. YouTube, RuTube, and VK Video are supported:

````markdown
:::video youtube
https://www.youtube.com/watch?v=K4TOrB7at0Y
title="YouTube example"
:::

:::video rutube
https://rutube.ru/video/f39214593c1933a60c57de704a5ee8cb/
title="RuTube example"
:::

:::video vkvideo
https://vkvideo.ru/video_ext.php?oid=-239594766&id=456239018&hd=3
title="VK Video example"
:::
````

For VK Video, copy the `src` value from the iframe that VK shows in "Share" / "Embed". A regular page URL like `https://vkvideo.ru/video-239594766_456239018` is not an embed URL and opens as an external link.

## Code blocks

For a code block, specify the language after the opening backticks:

````markdown
```bash title="terminal"
phpsoftbox up
phpsoftbox vite-dev
```
````

**Rendered example:**

<pre data-language="bash" data-title="terminal"><code>{`phpsoftbox up
phpsoftbox vite-dev`}</code></pre>

E-Doc renders it as a small window with language label, line numbers, syntax highlighting, and a copy button.

If you need a file title, add `title`:

````markdown
```json title="site.json"
{
  "title": "E-Doc"
}
```
````

**Rendered example:**

<pre data-language="json" data-title="site.json"><code>{`{
  "title": "E-Doc"
}`}</code></pre>

## Admonitions

For notes and warnings, use `note`, `tip`, `info`, `warning`, and `danger` blocks:

````markdown
:::note
A regular note next to the text.
:::

:::tip
A tip that helps complete the flow faster.
:::

:::info
Additional information that is not critical.
:::

:::warning
Before updating, check that user content lives in `local/storage/edoc`.
:::

:::danger
Do not store user files inside E-Doc core code.
:::
````

## Tabs

When you need to show several command variants, use tabs syntax:

````markdown
:::tabs
@tab Yarn
```bash
yarn add @edoc-space/plugin-openapi
```

@tab Npm
```bash
npm install @edoc-space/plugin-openapi
```
:::
````

**Rendered example:**

<div className="markdown-tabs">
  <div className="markdown-tabs__nav" role="tablist">
    <button type="button" className="markdown-tabs__tab markdown-tabs__tab--active" role="tab" data-tab="yarn" aria-selected="true">Yarn</button>
    <button type="button" className="markdown-tabs__tab" role="tab" data-tab="npm" aria-selected="false">Npm</button>
  </div>
  <div className="markdown-tabs__panels">
    <div className="markdown-tabs__panel markdown-tabs__panel--active" role="tabpanel" data-tab="yarn">
      <pre data-language="bash"><code>{`yarn add @edoc-space/plugin-openapi`}</code></pre>
    </div>
    <div className="markdown-tabs__panel" role="tabpanel" data-tab="npm">
      <pre data-language="bash"><code>{`npm install @edoc-space/plugin-openapi`}</code></pre>
    </div>
  </div>
</div>

Tabs are useful for alternatives such as `yarn` / `npm`, Docker / Workspace, or Linux / macOS.

## When MDX is needed

Use MDX when a page should contain a component:

```mdx
---
title: API
slug: api
---

import { OpenApi } from '@edoc-space/plugin-openapi'

# API

<OpenApi source="/storage/edoc/static/openapi.json" />
```

**Rendered example:**

<OpenApi source="/storage/edoc/static/examples/openapi.json" />

In this example, Markdown handles text and headings, while `OpenApi` renders a richer interface from a JSON file.

## Core components

Some components are included in E-Doc and do not require npm installation:

- `Hero` - the first screen of a page;
- `Section` - a semantic page block;
- `Grid` and `Columns` - layout grids;
- `Feature` and `Card` - compact cards;
- `Slider`, `Tabs`, `Testimonial` - visual blocks for site pages.

Import core components from `@/Components/Mdx`. If a page also needs an external component, import it from the npm package:

```mdx
import { Section } from '@/Components/Mdx'
import { DirectoryTree } from '@edoc-space/plugin-directory-tree'

<Section title="Structure">
```

## What not to do in MDX

MDX can execute frontend code, so use it intentionally:

- do not move a text-only document to MDX without a reason;
- do not put large data directly into JSX props when it can live in `static`;
- do not import user plugins from the core `package.json`;
- do not mix too many unrelated visual blocks on one page.

A good MDX document still reads like documentation. Components support the content instead of replacing it.

## How to choose a format

When in doubt, start with `.md`. When a concrete component need appears, rename the file to `.mdx` and add the import.

The URL does not change:

```text
docs/start/quick-start.md  -> /docs/start/quick-start
docs/start/quick-start.mdx -> /docs/start/quick-start
```

**Reader view:**

Both files open as the same page: [docs/start/quick-start](/docs/start/quick-start).

That makes it safe to start with simple Markdown and make the page richer only when needed.

## Blog publishing

The [opt-in blog](blog) reads a separate `{locale}/blog/` collection. MDX uses one application runtime and a private per-article graph, with helpers in its sidecar or `_shared`. Drafts never enter the public build. A new MDX body/dependency or private attachment requires production preparation; date/draft alone change visibility without rebuilding. Intentionally public static files remain public.

## Your own React component

Place shared author components in `components/` beside `site.json`. Relative ESM imports work in pages, docs and blog articles. This directory is intentionally public: keep private text, data and credentials out of it. Article-only helpers remain in its sidecar or `blog/_shared/`.

```tsx
// components/ComponentExample.tsx
import React, { useContext, useState } from 'react';
import { MdxLayoutContext } from '@edoc/mdx';
import './component-example.css';

export function ComponentExample({ label = 'Count' }) {
  const [count, setCount] = useState(0);
  const { locale } = useContext(MdxLayoutContext);
  return <button onClick={() => setCount(value => value + 1)}>
    {locale?.code} · {label}: {count}
  </button>;
}
```

This document imports `../../../components/ComponentExample.tsx`; use `../../components/ComponentExample.tsx` from `{locale}/pages/index.mdx`. `@edoc/mdx` exposes shared blocks and context from one React runtime. These two instances own independent state and receive the current locale:

<ComponentExample label="First" />
<ComponentExample label="Second" />

![Local React component in the default theme: independent instances and the current locale](/storage/edoc/static/examples/composition/local-component-en.png)


Component CSS joins the production output. After changing TSX/JSX, CSS, assets or an installed package, rebuild that site with `yarn build` in its prepared environment. The fingerprint tracks consumed sources and package metadata; stale builds fail closed with `theme.stale`/`blog.stale`. Date/draft-only edits do not require a build.

Import an installed package by name, as with `@edoc-space/plugin-directory-tree` above. Install it beforehand through `local/plugins/package.json`; it must export a compatible React component, declare React peer dependencies and avoid bundling its own React. HTTP requests never install packages. The resolver includes a stylesheet exported as `./style.css`. Missing modules/exports, unsupported runtime deep imports and another article's inputs stop preparation with a diagnostic. Public pages/docs still cannot import `blog/`, including through a transitive helper.


## Card links and block geometry

`linkPlacement="card"` makes the entire card a native link. Its content can include text, images and metadata; use `linkPlacement="title"` or `"action"` for independent links and buttons. See [site pages](site-pages).

MDX tabs retain Arrow/Home/End navigation, selection and independent instance state. Navigation joins the content without an extra gap; the inner panel has square corners. Video is centered in the available width and retains an explicit load button.
